- The Windows Safe Browser prefers installed Google Chrome with the user's default profile (extension installed from the ZIP, since branded Chrome ignores --load-extension; running chrome.exe is closed first so the launcher owns the process); in auto mode it switches once to bundled Chrome for Testing, which loads the installer's own extension/ with the stable manifest key, when installed Chrome's extension never pings /status or reports an older version (ping carries ?v=), so a missing or stale ZIP install never leaves an unmanaged browser (SAFEBROWSER_BROWSER=auto|system|bundled); the launcher bridge on 127.0.0.1 accepts only that extension origin.
- Exit, shutdown and restart require a card QR that kiosk-api staff-card resolves server-side to active personnel or an admin/director/teacher/staff role via the machine device key; students and parents are always rejected and no local password bypass exists.
- Remote power reuses the FaceGate kiosk_commands power queue and browser-heartbeat device status, so the machine appears with existing FaceGate machine controls instead of a parallel command system.
- Every leave path (Start/Win, Alt+F4/Tab, Ctrl+W/Q, log off, Task Manager, power/sleep buttons, shutdown) is vetoed or disabled while running and opens the staff-card exit page; lock policies are removed only after an authorized exit or power action.

- Ctrl+Alt+Del cannot be intercepted, so a 0.3s watchdog terminates Task Manager and system tools (cmd/PowerShell/regedit/Process Explorer) while running and refocuses the browser; elevated tools on admin accounts cannot be killed, so students use standard accounts.
- Teacher remote commands (lock, open URL, screenshot, shutdown/restart, logout) travel teacher → agent page → extension (agent-page-only message allow-list) → launcher bridge, so no new origin is trusted; kiosk adds --auto-select-desktop-capture-source so live view and screen capture need no picker, and screenshot falls back to the extension's captureVisibleTab instead of the Linux local daemon port.
- The launcher keeps --load-extension working for the bundled browser and, after the one-time switch, restarts at most once more when the extension has still never pinged within 90s (never loops), because without the extension the kiosk is an unfiltered browser with no login, policy, history, monitor or toolbar.
- The installer registers a Windows Native Messaging host com.bngss.wifi (wifi/wifi_host_win.py → WifiHelper.exe, netsh wlan, manifest path relative, allowed_origins only the stable extension ID) under Chrome, Chrome for Testing, Chromium and Edge keys, using the same message protocol as the Linux nmcli helper so the extension's Wi-Fi page works unchanged; netsh parsing avoids localized field names.
- The installer writes SAFEBROWSER_BROWSER (system or bundled), places the extension in ProgramData/BNG Safe Browser/extension (user-writable, Load unpacked once for installed Chrome) and registers a SYSTEM task that runs SafeBrowser.exe --update every 3h and at boot: it installs only a SHA-256-verified release from safebrowser-version.json silently, keeps safebrowser.env, and relaunches through a Users-group task, so updates need no UAC on student accounts.
- The installer sets HKLM browser policies (Chrome, Chromium, Edge) allowing camera, microphone, screen capture and geolocation for all http/https sites without prompts, removed on uninstall.
