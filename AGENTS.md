- The system is cloud-only (single hosted backend); standalone/self-hosted installers and the district hub were removed to keep the codebase focused on day-to-day school use.
- Database tables of removed modules (IoT, bus, district hub) are kept, only UI/functions removed — avoids data loss and lets features be restored later.
- Resolve existing Sonner imports to the shared SweetAlert adapter in Vite and Vitest, and render shared AlertDialogs with SweetAlert; preserve async decisions and queue background notices behind active confirmations.
- Share the work-area navigation catalog between the sidebar, department pages, and return links; keep existing protected routes and module toggles authoritative so regrouping never changes access or stored data.
- Store student_scores per (student, subject, semester, academic_year) with academic_year in CE; normalize BE input at write time and never default a missing term — scores must never land in or overwrite another term.
- Imported ปพ.5/ปพ.6 totals are authoritative; never recompute them from the system's weighting ratios.
- FaceGate agent packages are built by the Build FaceGate Agent workflow via scripts/kiosk/package-facegate.sh and published to the app-downloads bucket with a version manifest; download links in pages must resolve through useFacegateRelease instead of a fixed bundled zip — keeps the school's download identical to the packaged program.
- The tablet scanner workflow must configure identity only in its CI checkout after Capacitor sync, verify installer and launcher labels plus application ID from the final APK before publication, and publish versioned files with identity/hash metadata consumed by all scanner download links — prevents shipping mislabeled APKs and returning stale aliases without changing the main app.
- Save web and native push devices only through src/lib/pushRegistration.ts (register_push_subscription function, insert-and-accept-duplicate fallback, never client upsert) and retain pending native registrations until the database confirms; refresh user-scoped notification caches on resume/reconnect — client upserts hit RLS 42501 loops and silently drop devices.

- Use the managed Cloud backend for recovery; discard restricted school overrides, apply schema fixes through the migration tool, and access the school source only through AI_READONLY_DB_URL to preserve original data.
- Treat Drive copies as authoritative after byte-level verification and a saved registry; never count space as freed until Storage deletion succeeds, never auto-restore mirrors, and prune APKs only after verifying the manifest's current file.
- Preserve local failed writes until the server archive confirms receipt; scan dedup lookup failures must surface and block online writes rather than imply no scan exists.
- Authorize direct push sends server-side for service callers, privileged roles, or the recipient themselves; only explicit FCM UNREGISTERED errors may remove device tokens.
- Key-pool AI usage is logged once by keyPool with caller/function metadata; aiCall must not duplicate successful pool records.
- The Windows FaceGate installer (FaceGateSetup.exe) is built in build-facegate.yml with PyInstaller + Inno Setup, bundles the ONNX face models, reads settings from facegate.env, and is published as the facegate-windows release that download links prefer over the ZIP — schools get a no-Python, no-.bat install.
- Resolve automatic academic terms from academic_periods using the Bangkok date and synchronize is_current daily; preserve manual overrides and wait for both settings and period queries before reporting loaded values, preventing early term changes.
- Scope persistent CMS settings and cross-tab broadcasts to the active backend, reject empty caches, and propagate fetch errors instead of caching them as empty success; stale branding must recover on mount/reconnect.
- Keep score-status records strictly scoped to an explicit academic year and semester, surface fetch failures, and expire import-period caches at Bangkok date changes; unscoped legacy rows must not appear as current-term results.
- Protect kiosk face endpoints with server-validated active device keys or authenticated admin/director roles; provision browser credentials once per backend and send them only in headers so daily scanning remains login-free.
- Save admin term dates atomically through save_academic_period_dates; resolve school terms (including LINE attendance and legacy maintenance jobs) from the same academic_periods calendar and manual overrides, synchronize current flags on changes, and never rewrite historical academic records. Future term dates must be registered by admins rather than invented by maintenance jobs.
